# taskflow-api

A task management REST API built with **FastAPI**, **PostgreSQL**, **SQLAlchemy 2.0** and **JWT authentication**.

> Project 1 of a 15-project backend series — each project is built commit-by-commit as a teaching exercise.

## Features

- User registration with bcrypt password hashing
- JWT login (OAuth2 password flow, 30-minute access tokens)
- Full task CRUD: create, paginated list with status filter, read, partial update, delete
- Ownership enforcement — users can only touch their own tasks (404s reveal nothing)
- Alembic migrations, custom exception handlers, healthcheck, CORS
- 20 pytest tests (auth, CRUD, ownership, pagination); GitHub Actions CI

## Quickstart

```bash
# 1. Start Postgres
docker compose up -d

# 2. Install (use a venv)
pip install -e ".[dev]"

# 3. Run migrations
alembic upgrade head

# 4. (optional) Seed demo data — login: demo@taskflow.dev / demo1234
python scripts/seed.py

# 5. Run the API
uvicorn app.main:app --reload
```

Interactive docs: http://localhost:8000/docs

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://taskflow:taskflow@localhost:5432/taskflow` | SQLAlchemy URL. Tests override this with in-memory SQLite. |
| `SECRET_KEY` | `dev-only-secret-key-change-me-in-production` | JWT signing key — **must** be set in production |
| `ALGORITHM` | `HS256` | JWT algorithm |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `30` | Access token lifetime |

You can also put these in a local `.env` file (git-ignored).

## API reference

All `/tasks` routes require `Authorization: Bearer <token>`.

| Method | Path | Description |
|---|---|---|
| `POST` | `/auth/register` | Register — body: `{"email", "password"}` → `201` + user |
| `POST` | `/auth/login` | Login — form fields `username` (= email), `password` → `{"access_token", "token_type"}` |
| `POST` | `/tasks` | Create task → `201` |
| `GET` | `/tasks?skip=0&limit=20&status=done` | List own tasks, newest first |
| `GET` | `/tasks/{id}` | Get one task |
| `PATCH` | `/tasks/{id}` | Partial update (send only changed fields) |
| `DELETE` | `/tasks/{id}` | Delete → `204` |
| `GET` | `/health` | Liveness probe → `{"status": "ok"}` |

Task fields: `title` (required), `description`, `status` (`todo`/`in_progress`/`done`), `priority` (`low`/`medium`/`high`), `due_date` (ISO 8601, optional).

### Example

```bash
# Register
curl -X POST localhost:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"secret123"}'

# Login (note: form data, not JSON — OAuth2 convention)
TOKEN=$(curl -s -X POST localhost:8000/auth/login \
  -d "username=me@example.com&password=secret123" | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# Create a task
curl -X POST localhost:8000/tasks \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Ship project 1","priority":"high"}'

# List done tasks
curl "localhost:8000/tasks?status=done" -H "Authorization: Bearer $TOKEN"
```

## Project layout

```
app/
  main.py          # app wiring: routers, CORS, exception handlers, /health
  config.py        # pydantic-settings (env vars + .env)
  database.py      # engine, SessionLocal, Base, get_db dependency
  exceptions.py    # TaskFlowError + unhandled-500 handler
  core/
    security.py    # bcrypt hashing, JWT create/decode
    deps.py        # get_current_user (the auth gatekeeper)
  models/          # SQLAlchemy ORM: user.py, task.py
  schemas/         # Pydantic v2: request/response shapes
  routers/         # auth.py (register/login), tasks.py (CRUD)
alembic/           # migrations (versions/ are committed)
tests/             # pytest suite, isolated SQLite DB per test
scripts/seed.py    # demo data seeder
```

## Running tests

```bash
python -m pytest -q
```

Tests swap the Postgres dependency for an in-memory SQLite database (`tests/conftest.py`), so no Docker needed. 20 tests cover registration, login, token guards, CRUD, cross-user ownership (expects 404, not 403), pagination and filtering.

## Notes for learners

- Commits are small and ordered — `git log --oneline` reads like a tutorial. The jump from "CRUD endpoints" to "enforce task ownership" is deliberately one diff so you can see exactly which lines form the security boundary.
- `passlib` needs `bcrypt==4.0.1` pinned (see `pyproject.toml`) — newer bcrypt breaks passlib 1.7.4.
- Migrations were autogenerated with `alembic revision --autogenerate` and verified with an upgrade → downgrade → upgrade cycle.
